# Agent Note：项目级钩子信任是内容摘要授权

Status: implemented

[English](2026-11-14-project-hook-trust.md) | 中文

## 问题

会话工作目录可能带有一份桥接在进程启动时没看到的钩子配置。该文件属于项目内容：任何能写仓库的人都能让它指定一条 shell 命令，桥接随后会在每次匹配的工具调用上执行它。进程级 `configPath` 属于部署内容，可以保持受信任；发现的项目文件则需要人做出的明确决定，而且文件一变，该决定就必须停止生效。

## 决策

`dsh-hooks-claude-code` 在每个钩子点检查 `<cwd>/<projectHooksPath>`（默认 `.claude/settings.json`）。文件的精确字节生成 SHA-256 摘要；只有当已挂载的存储域为该目录保存了同一摘要时，项目级分组才会运行。`/hooks status` 显示摘要与信任状态，`/hooks trust` 记录当前摘要，`/hooks revoke` 删除记录。没有存储域时项目级钩子从不运行，因此缺失会以拒绝方式关闭，而不是静默信任仓库内容。

摘要覆盖原始字节而非解析后的分组：任何修改——包括注释或空白——都会暂停钩子，直到新内容被批准。解析结果按文件路径与 `mtime`/`size` 戳缓存，因此修改会在下一个钩子点被观察到，而不是等到下次进程启动。未受信任的项目每个内容版本只记录一条警告，并在没有其钩子的情况下继续；进程配置不受影响。

## 备选方案

**信任解析后的命令集合而非原始文件。** 两个不同的文件可能解析出相同命令，审阅结构的人看不到后来改变的字节。按字节哈希让批准绑定在人能检查的内容上。

**把信任存进设置文档。** 项目信任按目录存在，不应作为自由形式的用户配置编辑；存储域已经提供了本包拥有的键值记录，审批包对项目规则也采用同一做法。

**在受信任前只以观测模式运行项目钩子。** 只写日志的钩子仍然在执行仓库内容；完全跳过才是诚实的拒绝关闭状态。

**同时发现用户级与插件级配置。** 这些层次有自己的归属，不属于本次改动；按构造只有项目文件是不受信任的。

## 后果

仓库只有在显式 `/hooks trust` 之后才获得钩子行为，审阅者能在 `/hooks status` 中看到已批准的摘要。已通过进程配置运行钩子的用户不受影响。该命令需要已挂载的存储域；没有存储域的部署会失去项目级钩子，而不是获得隐式授权。信任随存储介质跨重启保留，但不跨内容修改保留，撤回也不要求文件仍然存在。

验证：`packages/experimental/hooks-claude-code/tests/trust.spec.ts` 覆盖未受信任时跳过并警告、status/trust/revoke、仅空白修改暂停已信任钩子、缺少配置以及存储域要求。
