# Agent Note：为已发布的仅日志事件写入可跳过标记

Status: implemented

[English](2026-11-15-ignorable-declared-log-only-events.md) | 中文

## 问题

`session-title-llm` 把 `session/title-llm-request` 与 `session/title-llm-usage` 两条辅助事件声明为 `SessionEventMap` 成员。声明的成员默认必读，词汇里没有它们的构建会以 `contains event type "session/title-llm-usage" (seq 18) unknown to this harness and not marked ignorable` 拒绝整份会话。对改变状态的事件来说这种拒绝是对的，但这两条记录只是纯信息性的用量记账：丢弃它们不改变日志其余部分的解释。

在本决策之前，事件信封的 `ignorable` 标记只有一个第一方写入者 `appendPluginRecord()`，它被限制在 `packages/experimental/` 与 `plugin:` 命名空间内。因此已发布的包无法提供一种既随包发布、又能让会话跨构建可读的信息性事件；若直接写入，则会让所有早于该声明的读取器拒绝会话。

## 决策

`Session.append()` 对 `SurfaceEventType` 之外的事件类型接受 `LogOnlyEventOptions`（`{ ignorable?: true }`），`SessionEventInput` 的第三个位置元素对同类事件承载它。`snapshotAppend` 把标记写入已提交的信封，并在表面（消息）类型上拒绝该标记：模型可见表面从不包含可跳过事件，静默丢弃消息历史会重建出不同的对话。运行时守卫与类型层重载共同保证：调用方无法把消息事件标为可跳过，非表面类型也不能携带表面元数据。

`session-title-llm` 为两条辅助记录传入 `{ ignorable: true }`。标记只影响读取器：认识这些类型的构建照常读取（用量统计不受影响），没有该声明的构建保留并跳过记录，而不是拒绝会话。声明了的状态变更事件仍保持必读默认；标记必须按记录说明理由，即其丢失不影响重建。

`plugin:` 记录路径不变：它仍是仅限实验包、且格式迁移只做尽力保留的逃生口。本决策扩充信封的写入者清单，不改变记录准入、`KNOWN_SESSION_EVENT_TYPES` 或 `SESSION_FORMAT_VERSION`；标记是按记录存放的信封数据，当前与相邻代读取器均已接受。

## 备选方案

**让所有已声明事件保持必读**。否决：用户可见的故障正是它，且每当已发布的包新增信息性记账就会重演，因为每次新增都会把共享同一安装的所有旧构建锁在外面。

**把标题记录写成 `plugin:` 记录**。否决：调用者限制存在的意义就是不让发布包保留格式迁移可能丢弃的状态；而且这会改变类型身份——已经存有 `session/title-llm-*` 的会话仍需要第二套词汇。

**在读取时允许一份「已知信息性未知类型」清单**。否决：它无法帮助已经存在的旧读取器，并把准入判断从写入方（知道载荷角色）挪到读取方（无法推断省略是否安全）。

**按类型名隐式地把信息性事件视为可跳过**。否决：标记必须保持是写入方的显式判断；默认必读使「忘记标记」表现为过度拒绝，而不是静默续接一份被掏空的会话。

## 后果

已发布的信息性事件现在能让会话在不同词汇的构建之间保持可读，而状态变更事件与消息历史在未知时仍然明确拒绝。缺少声明包的读取器只失去该项记账数据，不影响其他内容。写入方必须保持判断显式：只有丢失不影响重建的事件才能传该标记；将来携带状态的事件不得照搬这种做法。
