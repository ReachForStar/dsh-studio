# Agent Note: 关闭终端即释放 SSH 连接

Status: implemented

[English](2026-09-17-terminal-releases-ssh-connection.md) | 中文

## 问题

Web 面板中关闭 SSH 终端后，SSH 连接仍然开着。网关的 `ptyClose` 只关了终端通道，而 `ctx.sshSftp.connect(id)` 按定义派发一个句柄并一直池化，直到显式关闭或提供方拆除——网关又没有任何关闭连接的方法。因此为终端建立的连接会比终端活得久，在进程余下的生命周期里一直占着 SSH 会话与通道。

## 决策

网关记录每个 PTY 建立在哪条共享连接上。关闭最后一个持有该连接的终端时，连接一并关闭；自行退出的 shell 同样释放连接。释放按句柄身份比较，这正是提供方池化的 `connect` 返回的对象，且提供方已关闭时关闭操作是幂等的。后续 exec 与 SFTP 操作按需重新建连，因为已关闭的句柄会退出提供方的连接池。关闭连接失败只记录日志、不上报给调用方：终端已经关闭，而且这次关闭不是调用方能重试的事情。

## 备选方案

**新增 `disconnect` Remote 方法，由面板调用。** 面板必须自行判断连接何时不再需要，等于在客户端重复终端生命周期，而宿主本来就知道自己的最后一个终端何时消失。

**每次关闭终端都关闭连接。** 同一定义上的第二个终端会被抽掉连接。

**维持池化连接不变。** 空闲连接比创建它的终端活得更久，而面板没有结束它的手段。

## 后果

终端关闭后，SFTP 与 exec 会在下一次需要该定义的操作上付一次 SSH 握手。最后一个终端关闭时正在进行的传输会被中断，因为它持有的句柄被关闭；重试会重新建连。网关自身的测试覆盖最后一个持有者关闭、仍有终端持有时保留、远端自行退出时释放、按需重连，以及关闭失败的情形。
