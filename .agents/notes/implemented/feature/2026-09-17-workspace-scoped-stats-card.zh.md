# Agent Note: 统计浮层以工作区为口径

Status: implemented

[English](2026-09-17-workspace-scoped-stats-card.md) | 中文

## 问题

统计浮层只上报它所在会话的消耗。于是在同一工作区拥有多个会话的用户，每渲染一个会话就得到一张卡片，每张只回答该会话，而没有任何数字回答这些会话所属的工作区。用户要的是一张回答整个工作区的卡片。

## 决策

卡片通过 `useWorkspaces` 取得其所在会话的工作区，并把该工作区下全部会话的 token 求和。每个会话通过会话列表行携带的 `tokenUsage` 投影值上报 token——宿主会为列表中的会话（无论是否打开）投影这些值——当前会话则改用其实时投影，因为它比列表行更新。花费按会话计价：本客户端持有已结算消息的会话按每条消息自身的模型与结算时间逐条计费，其余会话按分桶总量以卡片的 `default` 费率估算，因为线上投影只带分桶总量、没有模型归属。因此按模型的拆分行仅在只有一个会话参与时保留；会话计时分组则保持原样——它们是当前会话的事实。会话列表未归入任何工作区时，回退到该会话自身的数字，行为不变。

## 备选方案

**在宿主侧聚合。** 费率卡是用户可编辑的客户端 settings 文档，宿主无法为会话计价；它只能返回 token，且要多一次往返，而卡片本就持有这些值。

**新增按模型的 usage 线上投影。** 这会让工作区估算变得精确，代价是一份新的持久化投影状态、其 schema 版本与缓存行——只为一张卡片，且是用户并未要求的拆分。

**只聚合客户端已打开的会话。** 这正是需求所拒绝的行为，而且会让数字取决于用户恰好开了哪些标签页。

## 后果

投影从未被缓存的会话在首次打开前不贡献任何数值，因此工作区总量可能少算从未渲染过的会话。当前会话的数值是精确的、其余是估算的，且卡片会在会话列表或投影变化时重新聚合。包测试覆盖跨会话求和、实时值优先于列表行、跳过空行、两条计价路径、单会话参与时的模型归属、拆分行消失，以及无工作区列出该会话时的回退。
