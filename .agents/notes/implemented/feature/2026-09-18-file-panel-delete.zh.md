# Agent Note: fork 文件面板的永久删除

Status: implemented

[English](2026-09-18-file-panel-delete.md) | 中文

## 问题

fork 的文件面板（`ui-polish` 的 `MutationDiffPanel`，会话视图的「文件」标签页）通过宿主 `/git/*` 路由浏览工作区目录树、就地编辑文件，但没有任何删除条目的方式——要删文件只能离开浏览器去用 shell 或系统文件管理器。上游的文件树（`ui-sidebar-files`）同样只读，而 `ctx.fs` 与 `workspaceFiles` Remote 也都没有删除操作，因此没有现成能力可调。

## 决策

面板自己的宿主接口新增 `POST /git/delete {cwd, path, recursive?}`。宿主用与 `read`、`write`、`list` 相同的 `resolveRepoPath` 守卫，把路径解析到请求 `cwd` 对应的工作区内（不允许 `..`、不允许绝对路径、解析结果必须落在工作区根下），然后：

- 拒绝工作区根本身；
- 使用 `lstat`，因此符号链接按它自身（链接）删除，而不是按它指向的目标；
- 文件直接删除；目录仅在调用方传 `recursive: true` 时删除——未带该标志的非空目录会以点名该标志的错误拒绝。

面板为目录树每一行渲染一个删除操作。它会打开一个 `Modal`（ui-primitives），弹窗点名该条目，目录文案会说明内容一并删除；只有确认按钮会发出请求。删除成功后重读根与所有已展开层级，并在被删条目正是当前选中路径（或其祖先）时清空编辑区选择。

## 备选方案

**让删除走 `ctx.fs` 与 `workspaceFiles`。** 本次否决：两者目前都没有删除操作，走这条路意味着新增接缝方法、在每个 provider 中实现（含 helper 方案的 `fs-ssh` wire），以及新增 Remote 方法——而这个面板的其他操作本来就走 `/git/*`。若将来出现面向模型的工具或第二个消费方需要删除，接缝才是正确的落点，届时面板可以切换过去。

**用原生 `window.confirm`。** 否决：面板运行在有设计系统的 Web 应用内，原生提示无法承载「目录内容一并删除」的措辞，也绕过了 locale 字典。

**软删除到回收站目录。** 否决：工作区没有回收站概念，隐藏的 `.trash` 会出现在文件树、`git status` 与模型自己的文件工具里。

**通过 `git rm` 或提交流程删除。** 否决：这个面板也要删除 git 未跟踪的文件，而用户要的是普通文件操作，不是暂存删除。

## 后果

删除在磁盘上永久且立即生效：没有撤销、没有回收站、没有恢复路径，包 README 已在已知限制中记录。删除目录会连同内容一起删掉，仅由确认文案与 `recursive` 标志把守。与它的 `/git/read`、`/git/write` 兄弟一样，`/git/delete` 位于文件系统接缝与每次调用的沙箱策略之外：守卫是工作区相对路径检查，而不是沙箱模式。大目录删除是单个同步请求，返回前面板不显示任何进度。

## 测试

- 宿主（`git-service.host.spec.ts`）：文件删除、未带 `recursive` 的非空目录拒绝、带内容的递归删除、工作区根拒绝、逃逸路径拒绝。
- 客户端（`mutation-diff.client.spec.tsx`）：确认弹窗拦截请求、取消不发请求、目录请求带 `recursive: true`、删除后重读目录层级。
- 手工：Web 文件面板打开 `deepseek-harness` 工作区，删除 `tmp/` 下的一个临时文件，列表中该行消失而兄弟文件保留。
