# Agent Note：永久删除会话

状态：implemented

[English](2026-11-10-session-permanent-deletion.md) | 中文

## 问题

归档只把会话从分组界面隐藏，日志仍然保留。想让对话彻底消失的用户在产品内没有任何入口；手工删除 `~/.dsh/sessions/` 又会留下 Workspace 注册表、归档与置顶集合以及客户端列表继续指向已不存在的 id。这个破坏性操作还需要明确边界：会话日志不是工作区文件，绝不能连带删除工作树或目录。

## 决策

删除是持久化能力加注册表清理，由一个 Workspace 命令协调。

- **接缝拥有产物。** `SessionPersistence.delete(id, options?)` 是唯一的破坏性持久化操作。后端删除会话的完整持久产物集合，包括历史代与会话本地文件；不存在时返回 `false`，因此崩溃后重试是幂等的。它是抽象方法：无法删除的提供方不能假装支持。
- **活动写入方优先。** 本进程或另一进程仍持有写句柄时，该方法以 `SessionAlreadyOwnedError` 拒绝。JSONL 后端在删除目录前取得内核写锁，并发写入方无法向正在删除的目录追加；已创建但未实体化的会话同样拒绝，因为它归创建者所有。
- **注册表清除全部引用。** `WorkspaceRegistry.deleteSession` 先拒绝本进程仍打开的会话（`WorkspaceLiveSessionError`）或提供方报告仍有工作的会话（`WorkspaceActiveSessionError`，复用归档准入 waterfall）。通过后才调用持久化，清除头部与路径缓存，把 id 从每个 Workspace 记录中摘除，并从归档与置顶集合中移除。未知 id 在同样的幂等清理后返回 `false`。
- **只删除日志。** 工作区文件与工作树绝不触碰；确认框写明该边界，实现除持久化后端外没有任何文件系统访问。
- **两次点击，避免误删。** 会话行菜单与已归档行提供永久删除。对话框第一次点击进入待确认，第二次才执行；取消不产生任何写入。成功后客户端刷新 Host 权威会话列表，行在同一次渲染代内离开所有分组界面。
- **路由报告拒绝。** `workspace/deleteSession` 把两种拒绝映射为 `workspace/session-open` 与 `workspace/session-active`；对话框本地化两者，其余错误显示 Host 原文。

## 备选方案

**客户端删除列表行。** 日志留在磁盘上，下次刷新会话就会复活；这个操作的存在意义正是数据必须消失。

**允许删除打开的会话。** 打开的标签页与路由会话仍持有活动状态，写句柄会向已删除目录追加。用本地化提示拒绝更诚实；用户先关闭会话。

**停止工作并删除合并为一次调用。** 归档需要这个组合，因为它保留日志供日后取消归档。删除是永久的，静默先停止工作会毁掉超出用户要求的东西；调用方必须显式停止。

**把日志删除放进注册表包。** 持久化拥有后端布局（项目目录、格式代、锁）；第二个文件系统所有者会重复这些知识，并破坏非 JSONL 后端。

## 影响

被删除的会话不再出现在 `stat`、`list` 与任何 Workspace 界面中，其日志目录已消失。会话打开或仍在运行时 Host 拒绝，因此界面只应在空闲与已归档行提供该操作，并对其余情况解释拒绝原因。引用该会话的附件、定时任务与后台任务不在本决策范围内，保持原样；会话列表与注册表只是不再暴露该 id。
