# 智能体笔记：从 opencode v2 采纳的循环与工具行为

状态：已实施

[English](2026-11-12-opencode-core-behaviors.md) | 中文

## 问题

opencode v2.2.7 处理了三类本仓库同样遇到的模型行为故障：回复在输出上限处被截断后回合以半句话结束；工具参数的类型与 schema 不符时报 `INVALID_ARGS`，模型要花一轮恢复；分叉会话的模型把继承的后台工作当成本会话的。三处修复都很窄，但都会改变模型可见或面向模型的行为，默认值与生效位置需要记录。

## 决定

三个独立行为，一处故障一个，默认保守。

- **有界输出续跑。** `AgentLoop` 新增 `maxOutputContinuations`（默认 `0`）。某一步以 `max-tokens` 结束时，若预算未用完，循环通过普通 next-step 收件箱注入一条带来源的用户消息（`output-limit`），因此它和其他用户输入一样进入日志、可重放。回合结束原因仍是 `max-tokens`（该原因具有粘性，后续完成的步骤不会抹掉截断事实）。需要续跑的部署显式设值。
- **校验前修复参数。** `defineTool` 在 `validateArgs` 之前对模型参数执行 `repairArgs`。只做唯一确定的转换：数字字符串转数字/整数、`"true"`/`"false"` 转布尔、数字/布尔转字符串、JSON 对象/数组文本转声明容器，并递归到声明的属性与数组元素。含糊或仍非法的值原样交给 `ToolArgsError`，失败信息仍逐条列出违规。记录的 `tool/call` 保留模型原始参数；展示回调校验原始值，因此重放旧参数不会抛错。
- **分叉归属提示。** `dsh-fork-notice` 在种子会话且非子代理的会话里，向 pre-step 追加一条带来源的用户消息（`fork-notice`），直到子会话自有日志已包含它。提示说明继承的未完成后台工作属于原对话，文件、分支与服务由双方共享。它就是普通用户消息：进日志、可重放，且只作用于分叉子会话。

## 备选方案

**默认续跑截断回复。** 会在运营方未要求时改变所有部署的回合数与成本；合法停在输出上限的回复（大文件转储）会被推着继续。配置项保留能力而不改变出厂行为。

**在每个工具里修复。** 逐个工具复制转换逻辑会漏掉调用路径，并把 schema 知识散落到每个实现；`defineTool` 是原生与 PTC 两条传输共同的校验点。

**把记录参数改写成修复后的值。** 会话日志必须记录模型真正发出的内容；展示与策略读取该值，静默改写会让重放与模型输入不一致。

**用系统消息或提示段落注入分叉提示。** 提示段落会作用于所有会话；系统消息会把事实移出分叉本已继承并展示的普通用户消息面。

## 后果

续跑在每次截断多一次请求，直到配置预算用完，并且即使续跑完成，回合结果仍记为 `max-tokens`。修复后的参数会改变工具主体收到的值，而日志保留原始调用，因此同时比较日志参数与执行参数的工具必须比较归一化后的值。分叉提示每个分叉会话出现一次；再次从分叉分出时不会继承，新分叉若是种子会话则会收到自己的提示。
