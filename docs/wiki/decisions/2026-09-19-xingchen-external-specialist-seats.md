# 星域专家席经 A2A 抵达（2026-09-19）

## 背景（现状与约束）

需求要求 Harness 成为「星辰多智能体协作系统」：星域路由把请求分给启明（通用开发）与天权、瑶光、天梁（架构评估、Bug 复现、分波交付），每个角色有自己的系统提示词与纪律，且要记录会话的角色与终止原因。

本仓已有的两条现成能力：预设（`dsh-agent-presets`）能给一个会话一套工具/提示词/技能组合，但一个会话只能挂一个预设，切角色等于换预设、重建会话；A2A 栈（[实体页](../entities/a2a-stack.md)）能把任务派给别的部署，且 `contextId` 直接就是一个会话。

## 备选方案（各方案优劣）

- **A. 四个本地预设 + `subagent_*` 工具**：角色在本进程内，模型可见同一套工具。但子代理共享父预设的组织（子代理加入父的组合），要在同一会话内切换「专家角色」就得改组合；且三个专家模型本是外部部署（Claude Code、Pi、OpenCode），本地预设无法表达。
- **B. 三个进程内专家会话 + 会话内路由**：由路由服务为每个专家开一个 dsh 会话并转发。要在 core/agent-loop 层面做多会话编排，改动落在 loop 而不是扩展点，违背本仓「新行为放扩展点」的约定。
- **C. 启明为原生代理，三位专家作为 A2A 对等端席位**：角色由派发时附加的章程定义，后端由部署配置；工具、命令、投影全部落在现有扩展点（`tools` / `commands` / `systemPrompt` / `sessionProjections`）；对等端续接复用 `contextId` 即会话 id 的既有语义。

## 决策（选定方案）

选 C。`@reachforstar/dsh-xingchen` 注册 `xingchen_route` 工具、`/review` `/bug` `/planning` 命令、路由提示词段落与 `xingchen` 会话投影；启明的章程写在 `xingchen-qiming` 预设的人设里，三位专家的章程写在包内 `charters.ts`，可按角色经配置覆盖。

## 理由（决策依据）

- 三个专家的真实载体是异构外部代理，A2A 是仓库已有的跨部署接缝，直接复用其「对等端只来自配置」的安全边界（模型不能自造端点）。
- 角色隔离的载体是提示词文本：派发前附加章程，使席位而非后端决定角色，换后端不动语义，也不需要为每个后端维护一份预设。
- 会话元数据用会话投影实现，是日志折叠，不需要新的事件类型与持久化格式，也就不会动 `SESSION_FORMAT_VERSION`。
- 复杂任务接力（先瑶光复现、再天权称量、后天梁排期）落在提示词纪律里，由路由代理按需多次调用，避免在 loop 里写死编排。

## 后果（影响与后续）

- 没有配置对等端的部署用不了三位专家：派发以对等端错误失败（命令路径落定为错误结果，工具路径落定为错误结果），不静默跳过。
- 对等端会话续接表在进程内存里（键 `会话 id + 角色`），重启后从新会话开始；对等端侧的历史仍在。
- 角色章程与投影形态由本包拥有；`docs/subsystems/xingchen.md` 与生成的 `ctx.xingchen` API 随 `gen-cordis-catalog` / `gen-doc-graphs` 更新。
- 前端尚未消费 `lastRole` / `lastTurnReason`：界面上的角色标签与路由切换属于后续批次。
